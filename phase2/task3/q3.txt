// 1. Defining the promise
const downloadFile = new Promise((resolve, reject) => {
  let success = true; // Simulate condition

  setTimeout(() => {
    if (success) {
      resolve("File downloaded successfully!"); // Passes data to .then()
    } else {
      reject("Error: Network failure."); // Passes error to .catch()
    }
  }, 1000);
});

// 2. Consuming the promise
downloadFile
  .then((message) => {
    console.log(message); 
  })
  .catch((error) => {
    console.error(error); 
  })
  .finally(() => {
    console.log("Operation complete."); // Runs no matter what
  });

Promise States

A Promise can be in one of three states:

Pending → Initial state, operation still running.
Fulfilled → resolve() called successfully.
Rejected → reject() called due to an error.

This example simulates downloading a file and shows how to handle success (then), failure (catch), and cleanup/final actions (finally) using Promises.







CLAUDE--------

This code demonstrates a JavaScript Promise — the pattern for handling something that finishes later (like a file download) instead of instantly.

What it does, step by step:

Creates a promise (downloadFile) that simulates a 1-second delayed operation via setTimeout. A success flag controls the outcome: if true, it calls resolve(...) with a success message; if false, it calls reject(...) with an error message.

Consumes the promise with a chain:

.then() — fires only if the promise resolved; receives the resolved value and logs it.
.catch() — fires only if the promise rejected; receives the error and logs it.
.finally() — fires either way, for cleanup/final logging.
Since success = true, after 1 second the output is:


File downloaded successfully!
Operation complete.
(Flip success to false and you'd get Error: Network failure. followed by Operation complete. instead.)

Underlying concept — Promise states: every promise starts pending, then settles into either fulfilled (resolved) or rejected — and it can only settle once, which is why .then() and .catch() are mutually exclusive for a single run.

In short: it's a minimal template for "attempt an async task → handle success → handle failure → always clean up," which is the core pattern behind virtually all real-world async JS (API calls, file I/O, timers) before/alongside async/await.
